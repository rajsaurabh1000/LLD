## Golden flow (say you’re following this out loud)

1. **Opening** (clarify-first) → 2. **Clarify + FR + NFR** (Section 1) → 3. **Framing after requirements** (user journey, consistency, defaults—**before** scale/architecture) → 4. **Scale** (optional tight) → 5. Core insight → 6. One diagram → 7. Pause → 8. One deep dive → 9. Bottlenecks → 10. Scaling / failures → 11. Tradeoffs with **defaults** → 12. Close.

---

## Anti–document-mode

| Reading notes | Strong Hire |
|---------------|-------------|
| Row-by-row tables | Two bullets, then *“I can go deeper where you want.”* |
| Service names first | User-visible outcome first |
| “A or B” only | *“I’d default to **A** because …; **B** if …”* |

Each `NN-hld-*.md`: **clarify-first opening** under the title, then **Section 1**, then **Framing after requirements** before **Section 2**—that order avoids “assuming requirements.”
